# КТ № 6. Allure — декор

Колосов Иван Максимович, группа 3П3.24.

## Запуск

```sh
python -m pip install -r requirements.txt
python -m pytest -v --alluredir allure-results --clean-alluredir
npx --yes --package allure@3.33.0 allure awesome allure-results --single-file
```

Матрица `cases.json` содержит по одному позитивному и негативному сценарию для каждой из 20 операций [Petstore v2](https://petstore.swagger.io/v2/swagger.json). `pytest` создаёт отдельный тест на каждый сценарий. `feature` показывает сущность (`Pet`, `Store`, `User`), `story` — операцию API, `severity` — значимость проверки. Фикстуры создают клиент и уникальные данные. В отчёте доступны шаги и HTTP-вложения.

## Результат прогона

20 из 20 позитивных и 8 из 20 негативных сценариев прошли. 12 негативных сценариев завершились с ошибкой. Ожидания взяты из Swagger там, где указан код для соответствующего сценария. Для операций с ответом `default` и для `Accept: application/pdf` ожидаемый клиентский отказ указан как рабочая гипотеза.

| Наблюдение | Операции | Ожидалось | Фактически |
|---|---|---|---|
| Неверный тип поля | `addPet`, `updatePet`, `placeOrder`, `updateUser`, `createUser` | `400` или `405` согласно сценарию | `500` |
| Объект вместо массива | `createUsersWithListInput`, `createUsersWithArrayInput` | `400` или `405` | `500` |
| Недопустимый статус или отсутствующий тег | `findPetsByStatus`, `findPetsByTags` | `400` | `200` и пустой массив |
| Формат ответа не поддерживается | `getInventory` | `406` | `500` |
| Запрос входа без пароля | `loginUser` | `400` или `401` | `200` |
| Запрос выхода без активной сессии | `logoutUser` | `401` или `403` | `200` |

[HTML-отчёт Allure](allure.html) содержит фактические результаты прогона. На странице файла нажмите **Download raw file**, затем откройте скачанный HTML в браузере. Для защиты можно открыть вкладку тестов, выбрать `Pet`, `Store` или `User` и показать шаги позитивного и негативного сценариев.
